# ADR-019: Code and open-data snapshots ship together

Accepted for the V2 implementation, 2026-09-09.

The app imports versioned data-snapshots during its static build. The earlier OPEN_DATA_REF metadata did not control those imports and could describe a different revision from the actual data. Snapshot ingestion already opens validated pull requests; merging a snapshot update and building that same commit is the supported publication path.

The Cloudflare build now records the checked-out commit as both code and open-data revision and rejects a differing OPEN_DATA_REF. data-live remains a data export/backup branch, not a hidden build input. All content, rights, output, links, SEO and budgets are checked in the deployment build. No promotion relies only on an earlier GitHub result.

A future independently versioned data deployment must actually fetch and validate an immutable manifest before it can replace this model. Until then, a snapshot PR is the explicit data update and rollback unit.
